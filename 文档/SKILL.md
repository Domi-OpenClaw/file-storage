# Knowledge Graph - 知识图谱构建

## 核心职责

1. **增量学习**：只学新增文件，避免重复
2. **知识提炼**：从文档中抽取标题、摘要、标签
3. **知识召回**：支撑对话中的知识检索

---

## 三步工作流

### Step 1: 读取文档

接收用户提供本地路径或 GitHub URL 的文档内容

### Step 2: 提炼知识点

从文档中提取 3~10 个关键知识点，每个知识点：
- 有明确标题
- 一句话摘要（≤150字）
- 归属标签（1~3个）
- 学习时间

### Step 3: 追加到索引

将知识点追加到 `knowledge-index.md`，格式：

```markdown
### [知识点标题]
- 摘要：[一句话核心内容]
- 标签：#标签1 #标签2
- 学习时间：YYYY-MM-DD
```

## 质量标准

| 指标 | 阈值 |
|------|------|
| 每文档知识点数 | ≥ 3 |
| 摘要字数 | ≤ 150字 |
| 标签数 | 1~3个 |

---

## 触发场景

| 用户说法 | 触发动作 |
|---------|---------|
| 「归档」+ 发文件 | 读取文档 → 提炼知识点 → 追加到索引 |
| 「学习知识库」 | 增量扫描知识库，新增文件触发学习 |
| 「查询知识」+ 关键词 | 从索引检索，返回匹配结果 |

---

## 质量红线（严禁）

- **数量不足**：单文档少于3个知识点视为不合格
- **摘要复制**：禁止直接复制原文段落作为摘要
- **重复学习**：已索引的文件不再重复提炼

---

## 持续改进（反馈回路）

当用户提出纠正（如"这条不对"、"补充XX"），必须：
1. 写入 `memory/long_term_memory.md` 的「教训记录」区
2. 更新 `knowledge-index.md` 对应条目
3. 下次归档同类型文件时优先调用教训
